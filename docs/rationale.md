# Design rationale: why each module, parameter and instruction

This page answers "why is this line here?" for the chip as submitted (branch `cmos5l`, RTL of decision entries 3, 10, 18 to 21; no RTL change after commit 109aff0 of 16 November 2026). Each row gives what the item does, why it was chosen, the alternative that was compared with its numbers, and where a reader can check it. The larger decisions have a full entry in [decisions.md](decisions.md) ("entry N" below); this page covers every module, parameter, flow setting and instruction form, including the small ones.

Measurements on this page that are not in a CI run, and how to repeat them:

- **Synthesis areas** of single modules: Yosys 0.70 with the typical-corner standard-cell liberty `sg13cmos5l_stdcell_typ_1p20V_25C` (`synth -flatten -top <module>; dfflibmap; abc; stat -liberty`), on the sources of commit 0b8e503, 17 November 2026. The alternatives are the comparison modules in [src/pe_rf_alt.v](../src/pe_rf_alt.v) and [src/g1_meas.v](../src/g1_meas.v); neither file is part of the chip (`info.yaml` does not list them). Areas are cell areas before placement (no buffers, no wiring).
- **Instruction use**: every `fw/*.s` (22 programs, 1,740 words) assembled at address 0 with [asm/pe_asm.py](../asm/pe_asm.py) and each word decoded by its opcode and function fields, same date. A count is static (a word in a loop counts once). "uses/files" means: number of words / number of programs that contain the form.
- **Calculations** are written out in the row.

Conditions: timing values are static timing of the routed layout at the three corners of the flow (slow 1.08 V 125 °C, typical 1.20 V 25 °C, fast 1.32 V -40 °C). Protocol timing values are logic simulations at 60 MHz with ideal pads, unless the row names SPICE or a data sheet. There is no silicon result. Rows marked **open** have a ground but no measured alternative; they are listed again in section 8 with what would close them.

## 1 Architecture

| Choice | What it does | Why | Alternative compared and its numbers | Evidence |
|---|---|---|---|---|
| Processor of four threads in a fixed barrel order, and pin changes as events at an absolute cycle time | Thread n executes in cycles c with c mod 4 = n; `OUT` writes an event (pin, value, time) that the pin's event slot executes in exactly that cycle | The time of a pin edge does not depend on the code path, on the other threads or on a late memory access; the RTL and the reference model can agree in every cycle | A cycle-counted processor (edge time = instruction count) and fixed-function blocks per protocol were compared only by estimate (entry 1); prior-art engines (RP2040 PIO, TI PRU-ICSS, XMOS XS1) are compared in [architecture.md](architecture.md). **Open**: no built alternative | `formal/core.sby` (barrel order, event rules), `formal/timed_out.sby` (all leads), the lockstep tests `test/test_core.py`; UART bit exactly 521 cycles at 115,200 bit/s ([README](../README.md)) |
| Four threads | Four program counters and register sets share one datapath | The four example protocols run at once in one program memory (`test_fw_full_all_four`); CAN uses two threads; the census and the stretch goals need at most two per protocol | Eight threads: each thread gets one instruction every 8 cycles (7.5 M instructions/s at 60 MHz), which halves every firmware rate (SPI target 1.2 to 0.6 MHz, JTAG, SWD), and four more ring entries of the thread state (more than 100 flip-flops each, 48.99 um2 per flip-flop) cost more than 20,000 um2 (calculation). Two threads: the four example protocols do not run at once | tests named; [isa.md](isa.md) 3.1 |
| Fixed slots: an idle, waiting or halted thread keeps its slot | A thread's slot is never given to another thread | A thread's timing cannot depend on the others (proved: `formal/core.sby` B2) | Giving idle slots to busy threads: the guaranteed rates (all threads busy) do not change, and one donated slot per 4 cycles would let the CAN receiver (about 124 cycles of work per bit) run 500 kbit/s (120 cycles a bit at 60 MHz), but the timing of each thread would then depend on the others (calculation) | `formal/core.sby` |
| Execute in the slot cycle; register selects decoded one cycle early | The instruction is fetched in cycle c - 1 and its register selects are decoded there | Takes the select decode off the slow-corner path | Decode in the slot cycle: -2.292 ns (run 40587591168); synthesis delay strategy: -0.862 ns (run 40967845275); with the early decode +1.560 ns (run 40955889046), all at 50 MHz (entry 5) | entry 5 |
| Thread state in a ring of 4 entries | Each cycle the ring turns by one; the entry at the head is the slot thread | No load-enable multiplexer (the library has no flip-flop with enable) and a 1-of-4 read | Register storage for 4 threads x 4 x 16 bits: ring 14,968.8 um2; 16 addressed registers with enables 23,223.7 um2 (+55 %); 16 latch words with clock gates 15,411.5 um2 (+3 %) and a latch timing check (synthesis, `pe_rf_ring`, `pe_rf_flop`, `pe_rf_latch`) | [src/pe_rf_alt.v](../src/pe_rf_alt.v) |
| Four data registers r0 to r3 | 2-bit register fields | Every program in `fw/` fits in 4 registers, including the USB device and the 10BASE-T station | Eight registers: ring 30,536.4 um2 against 14,968.8 um2 (+15,567.6 um2, synthesis `g1_rf_ring8`, `g1_rf_ring4`) and one more bit in every register field | [src/g1_meas.v](../src/g1_meas.v) |
| 16-bit word (instructions, registers, memory, host words) | One width everywhere | The IHP SRAM macros are 16 bits wide (`RM_IHPSG13_1P_*x16`), and one host word per instruction or data word | 18 bits would allow a 14-bit `TADD` immediate (removing the 16 `TADD 4095` words below) but needs memories the PDK does not offer | entry 3; section 5 `TADD` |
| Separate 16-bit time register T | `OUT`, `SAMPLE`, `WAIT` use T without a register field | The `OUT` word has no free bit (4 opcode + 4 pin + 2 register + 3 kind + 3 offset = 16) | T as a data register: one data register less and a register field that `OUT` cannot hold | [isa.md](isa.md) 11.2 |
| 16-bit times, horizon 32,767 cycles (546 us at 60 MHz) | An event must be issued at most 32,767 cycles before its time; the signed difference shows a past time as late | One 16-bit adder and compare per slot | 32-bit times: +64 loadable bits in T (4,296 um2 by the flip-flop and multiplexer cell areas) and +16 bits in each of 15 event slots; the slow UART receiver needs 11 more words to wait longer than the horizon | [isa.md](isa.md) 4.2 |
| Program and data memory: 512 x 16 and 1,024 x 16 SRAM macros | Code of all threads in one macro, frames and tables in the other | The USB device program with its descriptors (476 words) and one 1,518-byte Ethernet frame (759 words) must fit | 128 x 16 latches (97,044 um2) hold neither; 256 x 16 latches +50 % area and a layout stopped by a tool defect; latches for 1,536 words would need about 1,164,500 um2 (24,576 bits x 47.4 um2 per bit, calculation from the 128-word synthesis), nearly the whole 1,225,000 um2 tile; 2 x 512 x 16 macros: no frame buffer and 10 slew pins (entry 3) | entry 3 |
| Two dedicated line helpers (USB low speed, 10BASE-Te) on I/O ports | Bit-level work at line rate: line code, stuffing, CRC, receive clock recovery, timers | A thread executes one instruction every 4 cycles: 10 instructions per USB bit, 1.5 per Manchester half bit; not enough for either | One general serial line unit for both: 102,201 um2 against 39,808 + 52,161 um2, above the 50,000 um2 limit written before the measurement (entry 18). The USB helper also runs clocked and NRZ lines (SPI controller, JTAG, SWD clock, UART) for +4,355 um2 (row in section 3.2) | entry 18, [helpers.md](helpers.md) |
| One clock domain; host pins sampled with the chip clock | The SPI host port is synchronized and decoded in the `clk` domain | Static timing covers every path; no asynchronous FIFO | SCK as a second clock domain: **open**, not compared | [signoff.md](signoff.md) section 2 |
| Threads share data only through memory words | No inter-thread flag or mailbox | Only the CAN node uses two threads (a transmit flag in one word) | A hardware flag saves at most one slot per poll in one program of 22 (calculation) | `fw/can.s` |
| Declared clock 60 MHz | `info.yaml` clock_hz, `CLOCK_PERIOD` 16.667 ns | A USB low-speed bit is exactly 40 cycles and a 10BASE-T half bit exactly 3 cycles; the competition FAQ accepts 60 MHz; slow-corner flip-flop margin +1.682 ns (run 44005215480) | 50 MHz: 10BASE-T half bit 2.5 cycles; 40 and 48 MHz fail protocol margins; default placement at 60 MHz -0.675 ns (entry 4) | entry 4 |
| Tile 8x4 | 1,724.16 x 710.64 um | The largest size the rules allow | 6x4: +1.329 against +2.658 ns, 3 slew pins, 4 placement iterations (entry 2) | entry 2 |

# Tape-out checklist

Items to do or check before the final (tape-out) gds run and the submission. Each item gives its reason. The decisions behind them are in docs/decisions.md (entries 5, 6, 12, 13, 19 and 20).

## 1 Exit criteria for tape-out

There is no FPGA step: the design does not fit the only FPGA of the template workflow (iCE40UP5K, 154 % of the logic cells, run 41817455061; docs/decisions.md entry 12).

## 2 Flow configuration (src/config.json)

- [ ] Keep `"RUN_MAGIC_DRC": 0`. The shuttle takes the layout of one named run of the project's GDS action (shuttle FAQ, read 2026-11-07: the GDS action artifact is "the final GDS file that will be added to the ... submission", and "A project can't be submitted to a shuttle if its GDS action is failing"; the .github/workflows/gds.yaml files of the shuttle repositories TinyTapeout/tinytapeout-ihp-26b and TinyTapeout/tinytapeout-ihp-0p4 have no --harden step, read 2026-11-03). With the SRAM macros, Magic DRC reports 173,163 and 173,165 errors (runs 43925649736, 43941919810), all of the rule "N-Diffusion spacing to N-well in SRAM < 54 (NW.d exception)" inside the IHP macro layout, while the precheck's KLayout DRC with the PDK deck passes on the same layout; the KLayout deck is the DRC signoff (docs/decisions.md entry 20, E5). Earlier, without the macros: Magic DRC COUNT 0 (gds 43731920994, 8x4; gds 41380161509, 6x4).
- [ ] Keep `"PL_RESIZER_SETUP_SLACK_MARGIN": 1.5` together with the `set_false_path` to the latch cells in `src/pnr.sdc`, and `"OPENROAD_THREADS": 4`. A margin above 0 with the latch endpoints checked in place and route made the post-CTS resizer loop for hours (latch borrow slack 0.000; gds 40846505319 cancelled at 6 h 01 min); with the latch D pins out of the place-and-route checks the margin raises the slow-corner flip-flop slack from +0.487 to +1.682 ns on the same RTL in a 40 min job (docs/decisions.md entry 21). Do not drop one of the two without the other.
- [ ] Keep our keys above the line "DO NOT CHANGE ANYTHING BELOW THIS POINT" (CLOCK_PERIOD 16.667, PL_RESIZER_SETUP_SLACK_MARGIN 1.5, OPENROAD_THREADS, RUN_MAGIC_DRC, PL_TIMING_DRIVEN, PNR_SDC_FILE, SIGNOFF_SDC_FILE, CTS_SINK_CLUSTERING_SIZE, CTS_DISTANCE_BETWEEN_BUFFERS, and the SRAM keys MACROS, PDN_MACRO_CONNECTIONS, PDN_CFG, ERROR_ON_PDN_VIOLATIONS, FP_PDN_VSPACING, FP_PDN_VOFFSET, ERROR_ON_ILLEGAL_OVERLAPS, MAGIC_MACRO_STD_CELL_SOURCE, MAGIC_EXT_ABSTRACT_CELLS, MAX_SLEW_VIOLATION_CORNERS, MAX_CAP_VIOLATION_CORNERS and the design-repair keys, each with its reason in the file), and the part below that line identical to the template src/config.json of branch main except `FP_PDN_VPITCH` 67.44 (template 50.0; docs/decisions.md entry 19) (compared 2026-11-14: identical, every key and comment; the template main branch targets CMOS5L since the competition update of 2026-11-09). The question to Tiny Tapeout about these keys is answered by documents: the shuttle uses the layout of the project's own run, and precheck.py reads no configuration (TinyTapeout/tt-support-tools, branch ihp-sg13cmos5l, precheck/precheck.py, read 2026-11-03). Ask the organizers again only if the final submission form says that they build the layout again. Fallback if a person forbids the margin key, measured (default margin, latch D pins out of the PnR setup checks, gds 41813363136: 55 min 27 s, flip-flop slack +1.496 ns).

The gds workflow uses the moving reference `@ttihp27a` (template main flow since commit 8eff15d), so a new commit of the action can change the flow of the tape-out run. Last check (GitHub API commits, read 2026-11-15, unchanged since 2026-11-14):

  | Repository, branch | Newest commit at the last check |

Write the PDK and LibreLane versions of the tape-out run (resolved.json) in docs/verification.md.

## 4 Tape-out run, in this order

1. [ ] Commit the final RTL on cmos5l and push. The gds run of this commit is the tape-out run and the submitted run (E5, E6). About 41 min for the gds job (run 44557589283), inside the 6 h job limit; the whole workflow with the gate-level parts takes 3 h 20 min to 4 h (part 5, the 10BASE-T station, is the last job).
2. [ ] Read the result (section 5). If a criterion fails, fix it and make a new tape-out commit; do not submit a run of another commit.
3. [ ] Run the SDF job on the tape-out run (E9): Actions > sdf > Run workflow, with the id of the tape-out gds run. It checks out the commit of that run and loads its netlist and SDF files; no new gds run. About 1.5 h per part on the SRAM layout (SDF run 44055275323; 5 h at the slow corner before the macros), in two parts per corner (main tests; test_counter_sequence alone). Pass: every test passes at slow, typ and fast, `test_r3_sdf_delay` gives a clock-to-MISO delay of more than 0.2 ns (the annotation is in effect), and the "SDF ERROR" count is 4 (the header lines of the file; the job fails above 4, because then cells after the error have no delay; the SRAM macro entries are removed from the job's copy for this reason, docs/verification.md section 5). A tag whose name starts with "tapeout" also starts the job by itself after the gds run of the tag ends with success; that checks the gds run of the tag, which is a second run of the same commit. Icarus Verilog applies the cell delays only and runs no timing checks: STA stays the setup and hold check (docs/decisions.md entry 13).
4. [ ] Give the tape-out run in the submission (commit_id.json workflow_url, E6).
5. [ ] Tag the tape-out commit `rtl-freeze` and make its GitHub Release (flex/PREREG.md section 3). The Release carries the gate-level netlist of the tape-out run (`tt_submission/*.v`) as a file, with its SHA-256 in the Release text, beside the SHA-256 values that PREREG section 3 lists. Reason: GitHub deletes run artifacts after the retention time (90 days by default), so a tape-out run of 2026-12-10 loses its `tt_submission` artifact in March 2027, and every later gate-level result must name the netlist that it used.
6. [ ] After the tag, every new or changed firmware test gets its gate-level result through the gl_fw workflow (Actions > gl_fw > Run workflow) with `gds_run_id` = the tape-out run and `netlist_sha256` = the value in the Release; the job stops if the hash or `src/` differs. Run all test_rtl_* tests and every protocol row of flex/protocols.csv once on the tape-out netlist this way, so that the protocol count (docs/counting.md condition (d)) rests on the submitted netlist only.

## 5 Reading the result

- [ ] Read the timing from `55-openroad-stapostpnr/summary.rpt` and from `checks.rpt` of each of the three corners (`nom_slow_1p08V_125C`, `nom_typ_1p20V_25C`, `nom_fast_1p32V_m40C`). The job stops on a violation at any corner (`TIMING_VIOLATION_CORNERS`, `HOLD_VIOLATION_CORNERS` `*` in `tt_submission/resolved.json`; check that this is still so in the tape-out run, because an older flow version checked the typical corner only), but only the reports give the margin against the +1.1 ns target (E3).
- [ ] Read the slow-corner flip-flop setup slack from the first path (group `flops`) of `55-openroad-stapostpnr/nom_slow_1p08V_125C/checks.rpt` (constraints in `src/signoff.sdc`), and the worst hold slack at the fast corner. Reserve rule (docs/decisions.md entry 5): if the slow-corner flip-flop slack is less than the measured spread of the flow (0.55 to 1.1 ns for the same RTL), use the reserve with no slew violation: timing-driven placement with `set_max_transition 1.2` in the PnR SDC (gds 41856662241: +2.620 ns, hold +0.0722 ns, 0 slew violations); the stronger reserve is setup margin 8 with the PnR SDC (gds 41910131846), and its max-slew pins must be read on that netlist.
- [ ] Check `final/metrics.csv` (or the `gds metrics.csv` annotation of step `Signoff facts`): route DRC 0, antenna violations 0, LVS errors 0, power-grid violations 0, max slew, max capacitance and max fanout violations 0 at each corner (E8).
- [ ] Max fanout (E8): 0 at each corner in run 44557589283. Earlier layouts had 8 pins whose extra loads were antenna diodes (docs/decisions.md entry 17); if pins come back, the run summary lists them (step `Signoff facts`): trace their load cells before accepting them.
- [ ] Lint: `01-verilator-lint/verilator-lint.log` has no warning.
- [ ] Global placement: read `GPL-0047` (weighted routing congestion) in the `openroad-globalplacement` log; routing, not cell area, is the first limit (gds 41404293323: 1.0490 at the start, 1.0095 after 6 routability loops). Use the final `design__instance__utilization` (38.8 % in gds 44005215480 with the SRAM macros and the line helpers; 24.6 % in gds 43779857970 before them, 8x4; 30.6 % in gds 41404293323, 6x4) for area headroom, not the summary value of GPL-0019.
- [ ] Precheck: all checks pass (`precheck_reports/results.md`, E4); gl_test passes (E2).
